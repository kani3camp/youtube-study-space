# Primary Email notification channel

One logical primary Email channel per project, owned separately from alert policies. Both roots share this module, default disabled; this wave imports development only. The existing development channel was created by an independently approved operator POST before Terraform ownership.

Provide `GCP_MONITORING_PRIMARY_EMAIL` and `GCP_MONITORING_PRIMARY_EMAIL_CHANNEL` only as private secrets in both development plan/apply Environments. The caller maps only these explicit inputs, masks full values and fragments before authentication, and keeps channel ownership behind the explicit disabled `DEV_PRIMARY_EMAIL_IMPORT_ENABLED` gate. The import ID must belong to the development project. No mailbox or deployed channel ID belongs in source, Issue, public logs, Summary or artifacts. `sensitive` propagates through the channel label, module output and quota input; it is not encryption. Email labels can be persisted in the encrypted, access-restricted S3 state.

`force_delete=false` and `prevent_destroy` protect the channel and references. Import acceptance is import/read/no-op only, followed by complete no-op. A real operator plan found import1/update1 with identical before/after values and no unknown values: only the `labels` sensitivity metadata changes. This fails the unchanged import-only guard, so no apply was executed. Preserve sensitivity protection and keep ownership disabled; review a separately scoped state-metadata adoption route before enabling this gate. Do not classify equal values as an import-only PASS. CI needs only `monitoring.notificationChannels.get` for this existing channel; additional metadata permissions require approval, with no Monitoring Editor/admin grant. Creating channel/alert infrastructure is a separate normal-change operation and cannot pass the unchanged import-only guard.

The native channel is enabled and metadata matches the privately supplied destination. An unspecified Email verification status is distinct from `UNVERIFIED`; delivery/receipt has not been tested. No test email is sent by validation. Production channel creation/reference repair requires a separate operator decision; production Terraform remains disabled.

The review-only `terraform_email_adoption_gate.py` validates a proposed exception: development exact channel import, identical before/after values, no unknowns/drift/other imports/mutations, and only the email sensitivity mark. It rejects mailbox/project mismatches. This has no apply entrypoint and does not replace the existing guard. Backup bucket import must finish first. A protected execution route and explicit approval are still required; do not use this validator as authorization.
