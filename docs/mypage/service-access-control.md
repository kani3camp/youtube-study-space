# ServiceAccessControl — A

[Canon 04](https://app.notion.com/p/3ec357a8d0ce812f8520f787fedcc6bd) に従い、`service-access-controls/{channelId}` を `users` や `WebAccount` から独立したサーバー専用の認可ストアとして利用します。Phase A では MyPage のみを対象とし、既存 Bot の `!block`・YouTube Ban・通常の書き込み処理には接続しません。

---

## 保存内容とレスポンス

チャンネルは `UC` + 22 文字の YouTube ID で識別します。ドキュメントは以下の 4 フィールドのみを持ち、表示名・作業名・自由記述・連絡先は保存しません。

- `generation`: `1` 以上の単調増加する整数
- `updatedAt`: 更新日時
- `moderation` / `privacyDeletion`: 各制限理由（`active` は必須。有効時のみ `since`、固定 `reasonCode`、推測不能な 64 文字の小文字 16 進参照 `actionRef` または `requestRef` を保持）

### 制限コードと優先順位

| 種別 | 許可される `reasonCode` | 有効時の HTTP 応答 |
| --- | --- | --- |
| `moderation` | `MODERATION` / `SECURITY` / `POLICY_VIOLATION` / `LEGACY_COMPATIBILITY` | `403 SERVICE_ACCESS_RESTRICTED` |
| `privacyDeletion` | `PRIVACY_DELETION` | `403 DATA_DELETION_IN_PROGRESS` |

- 各制限理由は独立しており、同時に有効になる場合があります（両方有効な場合は **削除中の表示を優先** します）。
- 同じ状態・コード・参照の再適用ではリビジョンと世代を変えず、参照の変更を含む実質的な変更があった場合のみ世代を増やします。
- ドキュメントがない場合や、すべての制限が無効な場合はアクセスを許可します。取得・デコード・スキーマ検証に失敗した場合は `503 TEMPORARY_UNAVAILABLE` を返します（内部の制限理由・チャンネル・参照は API に出力しません。旧 `WebAccount.accessBlocked` はデコード互換のためだけに維持）。

## MyPage での適用箇所

### バックエンドの認可と整合性保護

- 先頭での確認: 検証済みカスタムプロバイダー UID を使い、`WebAccount` やキャッシュ参照より前に最新状態を読み取ります（通常のチャンネル確認・ログイン消費・Custom Token 発行・セッション完了・メタデータ更新に適用。サポート本人確認のチャンネル確認/`confirm` と公開規約ページは利用可能です）。
- 書き込み時のトランザクション整合: OAuth 消費、アカウント作成・更新、`firstWebLoginAt`、メタデータ更新・消去では同じ Firestore トランザクション内で制御状態を読み、保存したチェックポイントを照合してから書き込みます（競合時は再評価）。OAuth・YouTube API・トークン発行はトランザクションの外で実行し、発行前後にも最新状態を照合します（消費後の発行失敗でトランザクションを再利用しません）。定期メタデータ削除は引き続き実行可能です。
- 読み取り専用 `GET /api/mypage`: 通常取得・`view=current`・キャッシュヒット・共有処理への合流のいずれでも、HTTP 入口でリクエストごとに最新状態を 1 回読みます。チェックポイントに世代と更新時刻を含め、異なる世代のキャッシュや共有処理は再利用しません（入口での確認直後に制限が有効になった場合、確認済みの読み取りリクエストは制限時間内に応答を返すことがありますが、その後のリクエストは入口で拒否します。メタデータ更新を伴う場合は API 呼び出し前やトランザクション内でも再確認し、制限ストア自体の障害時は部分取得や古い値の `200` 応答へ変換しません）。

### フロントエンドの挙動

- 制限 `403` を受け取った場合、現在の状態・統計・チャンネルメタデータを同期的に破棄し、世代更新と中断によって遅延レスポンスを拒否します。定期取得・手動更新・表示復帰時の再試行はすべて停止し、専用メッセージ・ログアウト・法的文面・サポート・明示的な再ログインのみ残します（同じ UID で bfcache から復帰しても制限を維持）。
- 通常の `503` では既存の待機時間管理と古い値の表示を維持します。

## 信頼済み運用担当者用のモデレーション CLI

管理処理は `system/cmd/service-access-control` として提供し、ブラウザ向けの管理 API は追加しません（既存のエミュレーター専用 `mypage-operator-dryrun` は維持）。

- 実行モード: 既定は外部通信しない `plan` モード（`--check-config` もオフライン）です。`--execute` で実環境 SDK に接続し、本番環境では `--allow-production` も必須とします。
- 入力仕様: `--stdin` または非公開の通常ファイルを読む `--manifest` から 16 KiB 以内の厳格な JSON を受け取ります。
  - 全フィールド必須で `schemaVersion: 1`、`target: {environment, projectID, channelID}`、`operation`（`block` / `unblock` / `inspect`）、`actionRef`（64 文字の小文字 16 進数）、`reasonCode`、`confirmation`（`target` / `operation` / `actionRef` の完全一致が必要）を指定します。
  - `block` のみ固定 `reasonCode` を必須とし、`unblock` / `inspect` では空文字にします（未知・重複・`null`・大文字小文字違い・余分な JSON は拒否）。
- 実行境界: プロセスの `MYPAGE_ENVIRONMENT` と `GOOGLE_CLOUD_PROJECT` に固定し、プロジェクト別名の不一致・認証情報ファイル・エミュレーターへの転送は拒否します（選択プロジェクトの鍵なしメタデータ認証のみ許可）。
- 操作ごとの挙動
  - `block`: 制御状態のコミット・検証後、補助的に Firebase セッションの失効を試みます（失効に失敗しても保護状態は戻さず、再実行で失効を再試行します）。
  - `unblock`: `moderation` のみを消去し、`privacyDeletion` は保持します（`actionRef` は当該操作の対応情報であり、既存 block への CAS ではありません）。
- 出力と終了コード: 固定の `status` / `code` / `state`、世代、固定理由のみを出力します（対象・参照・パス・時刻・生エラーは出力しません）。
  - `0`: 成功 / plan 正常 / 設定正常
  - `1`: 取得不能 / 出力失敗
  - `2`: 入力・設定の拒否
  - `3`: 制御保存後のセッション失効の部分失敗

## 検証範囲とフェーズ B に残る課題

- フェーズ A の検証範囲: Go 単体・race テスト、Firestore Emulator での原子性・理由競合・旧トークン・メタデータ競合、匿名/合成ユーザーからの Firestore Rules 拒否、フロントエンド単体テスト、Playwright/Chromium による合成 QA（実 SDK・実ユーザーデータ・配備・移行は別条件）。
- 制御レコードの不削除: フェーズ A では制御レコードの削除・TTL・保持期限を設けず、`unblock` 後も無効状態のチェックポイントを維持します（保持ポリシー決定ではなく、「不存在 → block → 外部削除 → 不存在」という ABA 問題を防ぐため、世代番号を再利用しない設計としています）。
- フェーズ B での検討・確認事項
  - 全リビジョン・インスタンス・SDK の実行中処理完了待ち、旧処理再開後の新規利用との区切り、実行時再認証の経過時間上限。
  - サポート受付完了と関連 OAuth 消去、Bot・座席整理・Batch・BQ import・派生データ・ベンダー・ログ・バックアップを含む横断一覧と実環境保持の確認。
  - D02 規約適合性（[公開条件](release/README.md)）、D03 実値、CodeQL/セキュリティ、実環境の公開前確認。
