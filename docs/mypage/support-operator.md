# Trusted Privacy support operator (source only)

## 用途と制約

本人確認済みのアプリ内プライバシー申請を確認し、本文を含まない監査イベントとともに運用担当者の返信を1件、アトミックに保存する。開示やFirebaseセッション失効の申請は、独立して検証した操作証跡と返信の到達確認が揃った場合だけ完了できる。削除は既存の削除保護付き`Finalize`手順でだけ完了する。

申請参照やサポートのチャレンジは、運用担当者の権限を示さない。環境・プロジェクト・目的・申請参照・本人確認の証拠参照・安定した操作ID・想定リビジョンが一致する必要がある。返信は依頼された処理の完了を意味しない。削除処理が申請を確保した後は、新しい返信を拒否する。完了レコードには本文・返信・チャンネル・証拠・OAuthとの関連・送信インデックスを残さない。公開HTTPルートから運用担当者の状態は書き込めない。プライバシー受付の機能フラグは両方とも無効にしておく。

受入条件: 信頼済み権限がない場合や一致しない場合は拒否する。同一返信の再試行ではACK消失後も結果を維持し、内容の変更や別の操作は競合とする。完了には権限検証済みの操作証跡と配送証跡を必要とし、機密フィールドとインデックスをアトミックに消去する。削除の完了処理は、既存トランザクション内で最小限の完了監査イベントを記録する。エミュレーターとCLIのテストで、拒否と消去の範囲を検証する。

## 権限の検証と操作

`FirestoreSupportOperator`はサーバー専用ライブラリである。`OperatorAuthority`インターフェースは、信頼済みランタイムから実際の運用担当者の本人情報を取得し、対応する環境・プロジェクト・目的・申請・操作への最小権限を確認する必要がある。実環境用アダプターは意図的に含めていない。空のアダプター、CLIに入力した運用担当者名、受付チャレンジ、Firestoreサーバー認証情報だけでは呼び出しを許可できない。合成テストでは用途を限定した偽物を渡す。完了時には、アダプターが独立した操作証跡と配送証跡も検証する。呼び出し元が渡す証跡参照だけでは、その正当性を証明できない。

## 未接続の有人Google OIDC検証

運用担当者は1人である。`GoogleHumanOperatorAuthority`は実装のみの証拠検証器であり、署名済みトークンの取得元、JWKS、時計、一度限りのチャレンジをアトミックに扱うストアを外から渡す。コマンドやFirestore書き込み処理からは構築せず、OAuthクライアント・認証情報・トークン交換・Googleリクエスト・実チャレンジストアも導入していない。人間のIDトークンだけでは依頼された操作や返信到達を証明できないため、`VerifyEvidence`は拒否する。既定の運用CLIも引き続き`--execute`を拒否する。

設定するGoogle OAuthクライアントIDと、変更されない許可済み`sub`は、後の承認に向けた非公開ランタイム入力であり、リポジトリの値ではない。変更可能なメールアドレスではなく`sub`を本人識別のキーにする。監査に保存する実行者情報は、鍵で生成した仮名だけとする。検証器は、渡されたJWKS内の完全一致する鍵によるGoogle RS256署名付きIDトークンを受け入れる。文書で定めた2種類のGoogle issuer、単一の完全一致audience、存在する場合の`azp`、期限・発行時刻・nonce・確認済みメールアドレス・`sub`の完全一致を検証する。Googleアクセストークン、ADC/gcloud認証情報、サービスアカウントIDトークン、Firebaseユーザートークン、未署名JWT、別アルゴリズムのJWTはこの検証を満たせない。Google IDトークンはFirestore権限を付与しない。

`ReplyAuthorizationIntent`と`CompletionAuthorizationIntent`は、実際の操作から証拠参照・リビジョン・確認済み返信のダイジェスト・操作全体のダイジェストを導出する。5分間有効なチャレンジは、操作・環境・プロジェクト・目的・申請・証拠・リビジョン・操作ID・ダイジェストに結び付ける。保存するのはnonceハッシュ、鍵付きの対応情報、発行・期限時刻だけである。チャレンジストアは、対応情報全体の比較、そのアトミックな処理内での信頼済み時計の読み取り、有効かつ一致するnonceの一度限りの取得を行う必要がある。不一致ならnonceは利用可能なままにし、再利用は拒否する。
検証器はJWKSと署名の検証後にトークン時刻を確認する。消費処理が戻った後にも、トークンの期限・経過時間・発行時刻と、返されたレコードのnonce・対応情報・正確な5分の有効期間・発行と期限時刻・トークンの`iat`を再確認する。依存先の遅延でどちらかの期限を越えた場合は、nonce消費済みでも拒否する。共有ストアの仕様テストは現在プロセス内の偽物で実行している。将来の永続ストアも合格する必要があるが、ここでは検証していない。
同じ操作は新しいチャレンジとIDトークンで再試行できる。既存の返信・完了処理のACK消失時の冪等性は、運用担当者用トランザクションで維持する。将来の有人権限検証では、`FirestoreSupportOperator.Clock`が操作時刻を提供する。呼び出し元の`At`は監査時計に使わず、信頼済み時計がなければ拒否する。

任意のURL生成処理が出力するのは、運用担当者用OAuthクライアントID、ループバックのコールバック、`openid email`、内容を推測できないstate/nonce、S256 PKCEチャレンジだけである。受付情報・チャンネル・返信・証拠の内容は含めない。将来実接続する前に、state検証、デスクトップの認可コード交換、制限付きのGoogle公式鍵取得、永続的・アトミックなnonce保存、非公開設定、運用権限の一連のレビューを完了する必要がある。承認されれば1つのクライアントIDを両環境で使え、環境別クライアントは前提にしない。この設計は[Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect)、[デスクトップアプリのOAuth](https://developers.google.com/identity/protocols/oauth2/native-app)、[Google Cloudのトークン種別](https://docs.cloud.google.com/docs/authentication/token-types)に従う。クライアントの作成、ログイン、実JWKSへの接続、実行の有効化には別途承認が必要である。

`Reply`は、実際の検証済み受付と証拠参照、削除処理による証拠確保がないこと、想定する運用リビジョンを必要とする。非公開本文と鍵付きフィンガープリントを申請に保存し、同じトランザクションでサイズ制限付き監査イベントを1件作る。監査イベントに含めるのはスキーマ・環境・目的・操作・信頼済み実行者・鍵付き受付対応情報・鍵付き操作フィンガープリント・時刻だけである。本文・チャンネル・元の証拠・元の申請参照は含めない。申請が開いている間は、同じ内容と実行者による同じ操作の繰り返しは冪等とする。内容変更や別操作は競合にし、状態は`verified`のまま維持する。

`Complete`は`disclosure`と`revoke`だけを対象にする。信頼済みアダプターは、操作証跡と、合意した連絡手段で運用担当者の返信が届いた確認の両方を検証する必要がある。トランザクションで返信操作とリビジョンの完全一致を確認し、受付を最小限の完了マーカーに置き換える。申請IDインデックスとOAuthトランザクションを除去し、本文を含まない完了監査イベントを作る。受付の置換では、非公開本文・返信・チャンネル・証拠・チャレンジ・送信フィンガープリント・返信メタデータを除去する。これはGoogle OAuthの権限取消を実行・証明するものではない。セッション失効操作には、それ自体の独立した検証済み証跡が必要である。

`delete`の`Finalize`は引き続き既存の削除エンジンだけが制御する。このトランザクションは、既に受付の機密フィールドと関連インデックス・OAuthレコードを除去しており、さらに本文を含まない完了監査イベントを1件作る。古い受付を自動削除したり、過去の監査イベントを作り出したりはしない。実際の操作を実行する前に、監査の保持・廃棄ポリシーの承認が必要である。

## オフラインCLI

`system/cmd/mypage-support-operator`は`--environment`、`--project`、`--purpose`、`--request-ref`、`--proof-ref`、`--operation-id`、`--expected-revision`を明示的に受け取る。既定の読み取り専用プレビューは、これらを`MYPAGE_ENVIRONMENT`と`GOOGLE_CLOUD_PROJECT`に照合する。矛盾するプロジェクト別名、実認証情報やエミュレーターの環境設定は拒否する。`--action reply`では、`--reply-file`は権限が正確に`0600`の通常ファイルでなければならない。末尾のシンボリックリンク、サイズ超過、不正なテキストを拒否し、内容を標準出力やエラーに出さない。`--action complete`では、本文の代わりに`--reply-operation-id`・`--action-evidence`・`--delivery-ack`を非公開入力に含める。これらは申告された参照であり、単独では証拠にならない。CLIはFirestoreを読まず、実際の本人情報も解決しない。`--execute`はSDK初期化や変更を行わず、常に`TRUSTED_OPERATOR_ADAPTER_UNAVAILABLE`を返す。

## 公開前に確定する運用事項

実際の運用担当者用処理を実装する前に、所有者は実際の本人識別元と最小権限範囲を指定し、監査の保持とアクセス制御を承認する必要がある。返信の配送と到達確認の手順を整え、利用可能なFirebaseセッションがない人向けの有人窓口も公開する必要がある。返信手段はアカウント削除とセッション喪失に対応しなければならない。D02の設計判断は、外部のGoogle権限取消を検出するためだけにリフレッシュトークン保存や定期取得を追加しないことである。規約適合性と、取消後の保持済みAPIデータの扱いは未確認であり、検証・規約適合性レビューで確認する。D03の連絡先実値も未決定である。0Bの条件と両方の機能フラグは維持する。合成テストの成功やソースのマージは、プライバシー機能の公開を意味しない。
