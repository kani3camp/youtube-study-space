# MyPage 増分原価モデル

[入力値](cost-model.json)と[計算スクリプト](../../mypage/scripts/cost-model.py)で、利用量・構成・集計方式を変えた試算を生成する。入力の`verifiedAtJST`は価格確認日であり、現在の料金や請求実績を保証しない。再利用時は対象リージョンと公式料金を再確認する。公式出典は入力の`sources`に集約する。

```sh
python3 mypage/scripts/cost-model.py --test
python3 mypage/scripts/cost-model.py --output /tmp/mypage-cost-report.md
# 感度を変える場合は入力の private copy を作り --input で指定する。
```

生成表は作業資料とし、リポジトリへ重複保存しない。請求との照合と未完の実測は[公開受入 #1133](https://github.com/kani3camp/youtube-study-space/issues/1133)で追跡する。

## 構成と入力の意味

- 採用構成は`hosting-run`（Firebase Hosting + Cloud Run API）である。`armor-run`は不採用のLB / Armor / Run Web比較シナリオで、計算スクリプトの先頭表はこの旧構成の感度比較を示す。採用構成の値は`hosting-run`の行を使う。構築状態や承認済み予算を示す表ではない。
- DAU・滞在時間・原記録件数・インデックスエントリー・月次検索の平均・キャッシュヒット・課金経過時間・転送量・書き込みの再試行は、すべて試算入力である。小規模な合成テストデータや端末側SDKの遅延を、利用者平均・Run CPU・請求値に一般化しない。
- 概要、セッション完了POST、明細、全Bot利用者の月次書き込みを別々に加算する。5分間隔の定期取得に変えても、セッション回数やApp Check評価回数が同じ割合で減るとは仮定しない。
- 月次検索は最大2文書だが、API全体が2 readになる意味ではない。認可・WebAccount・User・空の座席クエリの最低課金、メタデータ更新、トランザクション再試行、インデックスエントリーを含めて評価する。キャッシュヒットでも認可の読み取りは必要である。
- `limit(1001)`はインデックス走査の課金上限ではない。Query Explain Analyze自体も課金される。明細の重み付き利用枠は実読み取り数と区別し、失敗・ACK不明・利用枠管理の増分も計上する。
- Runの秒数は割当資源の課金経過時間の仮定である。100ms単位の丸め・起動・同時実行は別途確認する。静的キャッシュでも初回訪問とリリース更新時の再ダウンロードは残るため、HTML/APIのno-storeとは分けて扱う。
- App Check / reCAPTCHAは、組織全体の評価回数に対する増分を扱う。定期取得とは独立しており、別プロジェクトの利用も確認する。

## 会計と除外

Firestore無料枠はプロジェクトの対象DB・日単位、Run無料枠は請求先アカウントの全プロジェクトで共有する。Hostingは全サイト・チャネルと旧リリース保存量を合算する。利用可能な残量を入力で明示し、DEV/PRODで二重控除しない。HostingのGBとFirestore / LBのGiBを区別する。

既存処理は基準となる利益に含め、新しいWeb機能の増分だけを引く。候補会費・手取り率・為替・税は仮定であり、商品価格の承認ではない。アップグレードは既存会費との差額だけを収益に加える。Botの書き込み、DEVの変動費、イメージ保存費も別に加算する。

ストレージ、インデックス、古いリリース、ログ保持、バックアップ/PITR、移行・削除、Auth / Identity Platform、Monitoring、YouTube利用枠、不正利用、税・手数料・返金は必要に応じて追加する。入力が0でも無料の証明にはならず、このモデルを完全な請求総額や厳密な費用上限とは呼ばない。

実運用のインスタンス上限、Budget通知の実着信、異常利用の監視は[公開条件](release/README.md)と[E2E](release/e2e.md)で確認する。
